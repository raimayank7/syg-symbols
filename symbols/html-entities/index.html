Symbols

HTML entities for symbols

There are three ways to put a symbol such as © into a web page, and all three show the same thing to the reader. This page explains which to use and gives a table of the named codes for the symbols on this site.

The three ways

  1. Paste the character itself: ©. This is the modern way. It works as long as the page is saved and served as UTF-8, which is the standard today. Make sure the page has <meta charset="utf-8"> near the top.
  2. A named entity: &copy;. An ampersand, a name and a semicolon. Names are easy to read in the source, but only some characters have one.
  3. A numeric reference: &#169; (decimal) or &#xA9; (hexadecimal). Every character can be written this way. The number is its Unicode code point; the hex form matches the U+00A9 style used in character charts.

Five characters you must always escape

These have a job in HTML itself, so they cannot be typed bare inside text or attributes:

  • &lt; for < (less than)
  • &gt; for > (greater than)
  • &amp; for & (ampersand)
  • &quot; for " (double quote, inside attribute values)
  • &#39; for ' (single quote, inside attribute values)

The invisible ones

Some entities are useful because you cannot see the character when it is pasted: &nbsp; is a space that never breaks across lines (use it between a number and its unit, as in 10&nbsp;km); &shy; is a hint for where a long word may be hyphenated; &ensp; and &emsp; are wider spaces. For these, the named form is the better choice, because the next person to edit the page can see it.

Symbols in CSS and JavaScript

Entities work only in HTML. In a CSS content property, write a backslash and the hex code: content: "\2192" draws →. In JavaScript strings, write "\u2192"; for characters above U+FFFF, such as most emoji, use the form "\u{1F600}". Each symbol page on this site gives the CSS and JavaScript forms.

Common mistakes

  • Leaving out the semicolon. &copy without it works for a few old names and fails for the rest. Always close with a semicolon.
  • Wrong capitals. Names are case-sensitive: &Omega; is Ω and &omega; is ω.
  • Escaping twice. If a page shows the text &amp;copy; to readers, the code has been escaped once too often by a program on the way.
  • Garbled characters such as â€™. The page was saved as UTF-8 but is being read as an older encoding. Add the meta charset line and make sure the server does not announce a different one.
